# Coordinator startup

Locate PLANS_DIR or the explicit plans checkout and determine scope. Startup is a compact status/recovery pass, not permission to research or implement every draft. Read the scope profile first and honor repository instructions already loaded; do not reread them. Inspect Git status and fetch the configured plans remote without modifying local work. Report unavailable remotes as stale; do not require old conversation history.

Discover scoped plan IDs, lifecycle directories and Current state sections with targeted searches. Read full active plans only when needed to recover assignments/blockers. For drafts, list titles and next actions; do not open product source, machine inventories, completed plans, historical handoffs or trial logs unless an active task requires them. Read only new or changed handoffs for active assignments, using recorded review revisions. Do not create a second manually maintained status index.

Check the synced owner/transfer record. Read coordinators/sync.md and use plan-sync when reconciliation, publication or ownership changes are needed, rather than loading that procedure on every boot. Before changing plans read working-agreement.md and plan-spec.md. Absence on this machine does not prove another machine's coordinator stopped; record authorized ownership changes before dispatch.

When runtime setup is authorized and needed, read the herdr skill and the relevant workspace section of coordinators/updates.md: inspect/reuse or create one named workspace, keep a dedicated coordinator tab and by default, a separate labelled tab per worker in that workspace. This user-selected topology overrides the generic Herdr sibling-pane default; the coordinator may choose a split pane when it judges that layout better suited to the work, without additional approval. Use targeted command help, not every command group. Record returned identities locally and preserve user focus. External control requires explicit named-session authorization; do not fake HERDR_ENV. Otherwise report runtime setup pending.

Finish startup with a short brief: active assignments, user decisions, available drafts and next action. Stop there unless the user also requested refinement or execution. Do not run plan-write or product investigation implicitly. Load fallback guidance in coordinators/updates.md only when configuring it: one owner, five-minute default, explicit scheduler authority and cancellation when inactive/transferred. An idle session cannot check files by itself.
